Scripts used on my system. `startup` is a directory of scripts executed at session startup; `~/.local/bin` is added to `$PATH` so you can call the helpers from your terminal. Helpers are Niri-specific where there is no portable equivalent.

## Full list

| Script                     | Description                                                                                                                                                                                                                                       |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `at_startup`               | script executed by the Niri startup config; it iterates the `startup` directory and runs executable `*.sh` files, skipping names beginning with `_` or ending in `.bak` |
| `bak`                      | add `.bak` to a file\[s\] or remove `.bak` if already set, used to temporary disable some scripts  |
| `brightness`               | main script that simplifies brightness controll and sends OSD like notification                                                                                                                                                                   |
| `caffeine`                 | my tiny implementation of an idle inhibitor. Uses systemd-inhibit under the hood, can also prevent laptop from sleep when closing the lid. example: `caffeine handle-lid-switch`. Used from `startup/auto_caffeine.sh`                 |
| `powerprofile`             | tool to cycle power profiles. Written for **asusctl**, but with some tweaks might be modified for power-profiles-daemon                                                                                                                           |
| `genid`                    | "you give me a string, I give you md5sum hash of it"                                                                                                                                                                                              |
| `perforun`                 | `powerprofilesctl` based tool. Executes provided aruments to in performance mode, inhibits sleep and when finished restores previous power profile. I use it for games                                                                      |
| `playerctl_volume`         | Increase / decrease volume for the current active player (not the system sound), for example if a media player is active, running `playerctl_volume 0.1+` will increase its volume by 10%                                                           |
| `powersafe`                | Applies optional desktop power-saving settings through a root-owned helper (`/usr/local/sbin/dotfiles-powersave`)                                                                                                                                 |
| `ppjson`                   | pretty prints raw json strings.                                                                                                                                                                                                                   |
| `scase`                    | covnerts given file name or string to given case (by default to snake case), used from nemo. example: `scase -f "file with spaces"` will rename `./file\ with\ spaces` to `./file_with_spaces`. Also can set to kebab case or camel case (experimental) |
| `screenshot`               | screenhots the screen. If `--select` is passed, uses flameshot (if found) or slurp to select area                                                                                                                                                 |
| `toggle_bluetooth`         | Toggles bluetooth on/off, when turning off, also turns the music off. When turning on, tries to connect to the last or preferred device. To set preferred device, run `bluetoothctl devices Paired` and put the line with the device you want to `~/.config/.bluetooth.pref`. |
| `mictoggle`        | Toggles microphone state on/off and sends notification with current state                                                                                                                                                                         |
| `screenrec`         | similar to `screenshot`, with no argument starts to record your screen, with `--select` firstly lets you select the recording area. If you run it when recording is already on, will end recording                                                |
| `sshs`                     | starts an ssh session with given identities: `source sshs ./ident_1 ./ident_n`                                                                                                                                                                    |
| `dotfiles-lock`            | lock helper (Niri's `swaylock`) |
| `niri-startup`             | guarded one-time Niri session startup for bars, daemons, wallpaper, and terminal |
| `start-niri`               | environment wrapper for the SDDM `Niri (Dotfiles)` session |
| `toggle-waybar`            | hide Waybar when it is running, or start it again with the active compositor's config |
| `toggle-scratchpad`         | show the scratchpad or put it away, bound to `Super+S`. Hyprland has no scratchpad of its own, so this is a script rather than a one-line bind: the same key both opens and closes, and nothing outside the window can close it on this Hyprland because every dispatch route is broken (`hyprctl dispatch killwindow` expands to invalid Lua, and `hyprctl eval 'return hl.dsp.window.close()'` answers `ok` and leaves the window open). So it drops a flag file instead, which `scratchpad-session` is watching |
| `scratchpad-session`        | the command the scratchpad window runs. Gives an interactive shell and leaves a watcher on that flag file which kills kitty when the toggle drops it. Killing kitty rather than exiting the shell is deliberate: `nvim` in the scratchpad followed by `Super+S` would otherwise leave nvim running with no window. Holds kitty's pid captured *before* its `exec`, because after the exec `$PPID` would be the shell's parent rather than the terminal's |
| `clipboard-watcher`         | keeps cliphist fed, started from the Hyprland autostart. This was a bare `wl-paste --watch cliphist store` with one exec and no supervision, which worked right up until wl-paste exited and then clipboard history was dead for the rest of the session with nothing to notice. wl-paste does exit by itself in ordinary situations -- an app taking the clipboard with no text, or a cleared selection -- so this restarts it. Restarts are safe because cliphist collapses a store that repeats the previous entry. Takes a `mkdir` lock so a second copy cannot race on the database; `mkdir` is atomic where `touch` is not |
| `clipboard-history`         | clipboard picker, bound to `Super+V`. Was a one-line pipeline inline in the bind that **wiped the clipboard every time it was cancelled**: rofi exiting on Escape is not a failure, it is how you change your mind, and the pipeline did not treat it as one -- rofi printed nothing, `cliphist decode` read nothing and exited 1, and `wl-copy` was handed empty stdin, which is how you clear a clipboard. Measured: a clipboard holding `BEFORE-CANCEL-TEST` came back empty after one Escape, which read as "the clipboard is not saving things". This checks the *selection* rather than the exit status, because rofi exits 0 when cancelled |
| `toggle_rofi`              | wrapper script to provide any rofi related menu / script with the toggle functionality (close if already running) executes provided arguments. Example: `toggle_rofi rofi -show drun`                                                             |
| `una`                      | extracts any kind of archive so you dont have to memorize "how the hell do I extract a .zip, .tar or .rar"                                                                                                                                        |
| `update`                   | updates your system, cleans up some unnecessary .desktop entries from `/usr/share/applications` (see definitions inside script), removes orphans packages afterwards and also prompts you to reboot after an update. You can pass arguments to the underlying pacman with --. Optionally you can pass --reboot or --no-reboot to avoid prompt                                                                                                                                                                                                                  |
| `volume`                   | similar to `brightness` - increases / decreases the volume and sends fancy OSD like notification                                                                                                                                                  |
| `whendone`                 | sends a notification when passed command finished: `whendone sudo pacman -Syu`                                                                                                                                                                    |
| `wallpaper-switcher`        | opens **matuwall** on the wallpapers folder, bound to `Super+W`. An argument is taken as a folder name under `~/Pictures/Wallpapers`, or as an absolute path. It was once theme-aware -- it asked `theme-apply` which folder the current palette named -- but the theme is fixed now, so there is nothing to ask and the picker simply opens the folder it is given |
| `awww`                      | **shim, not the real binary.** Sits in `~/.local/bin` (first on `$PATH`) and wraps `/usr/bin/awww` so any wallpaper change that does not name a transition gets the expanding circle (`--transition-type center --transition-fps 60`). It only touches the `img` subcommand and only when `--transition-type`/`-t` is absent, so `awww restore`, `query` and the rest pass straight through. This exists because **matuwall sets the wallpaper itself** through its own awww backend and offers no transition option, and its `[hooks] on_apply` runs *after* the apply, too late to change the animation. `AWWW_SHIM_DEBUG=1` prints the final command line. If you ever delete this file, also `rm ~/.local/bin/awww`, or the stale copy keeps shadowing the real binary |
| `themesw`                  | **removed.** The desktop theme picker, was bound to `Super+T`. It listed the palettes under `themes/` in a rofi dmenu and called `theme-apply`. The theme is fixed now, so there is nothing to pick |
| `theme-apply`              | **removed.** Rendered every app's colours from `themes/<slug>/palette.conf` -- the bar, launcher, terminal, GTK, Qt, mako, and also nvim, VS Code, btop, wlogout and fastfetch. Its output for the E-ink palette is committed under `config/`, so the desktop keeps those colours with nothing running to regenerate them. `themes/e-ink/palette.conf` is kept as the record of where the values came from |
| `xdg-terminal-exec`        | direct definition of the xdg-terminal handler. Some apps use it to determine which terminal emulator you use and execute something inside it                                                                                                      |
